# 周邊照片整合審查

Claude Code 實際回報模型：`claude-opus-5-5`。審查結論：沒有阻擋上線的問題。以下為原始唯讀審查結果；當時尚未包含後續修正。

**結論：沒有阻擋上線的問題。** 15 張照片對應 8 項商品，PVC 透卡只有正面；只有「Q 版流沙」標示照片待補，沒有新增不存在的商品圖。15 組 `img` 的 `width`／`height` 與 `srcset` 寬度描述都和 `assets/merch-manifest.json` 一致。我看過書籤、NFC、PVC 和皮革吊飾的裁切，商品本體與圖案都沒有被切到。下面依嚴重度列出可處理的項目。

## 缺陷（不阻擋上線）

**1. 中｜效能：`sizes` 和實際顯示寬度差很多，直式圖在桌面一定會下載 1400 版本**
- 位置：`index.html:1`，每張 `.merch-photo img` 的 `sizes="(max-width: 760px) 82vw, 40vw"`；搭配 `versions/11-theatre-scrapbook/style.css:390`、`:406` 的固定高度。
- 原因：圖片高度固定為 310px（手機 280px），所以直式圖實際只顯示約 126–212px 寬。但 `sizes` 宣告的是 40vw，在 1440px 寬的螢幕上等於 576px。結果即使是 DPR1 螢幕，書籤、PVC、皮革正面、票卡夾和流沙都會選 1400 版本。以 1440／DPR1 計算，未展開的正面圖合計約 546KB，其中約 350KB 可以省下。例如 `holder-front` 114KB 對 34KB，`sand-front` 199KB 對 60KB。
- 建議：由 `scripts/prepare-merch.py` 依長寬比算出每張圖的 `sizes`。以流沙正面為例，可寫成 `sizes="(max-width: 760px) 192px, 212px"`，其中 212 = 310 × 957 ⁄ 1400。

**2. 低｜可及性（WCAG 2.5.3 名稱需包含可見標籤）**
- 位置：`index.html:1`，每個 `a.merch-photo` 的 `aria-label`。
- 原因：畫面上顯示「查看大圖」，但 `aria-label` 是「查看明信片正面大圖（另開分頁）」，可見文字沒有完整出現在名稱裡，用語音操作的使用者說「查看大圖」可能無法觸發。
- 建議：改成 `aria-label="查看大圖：明信片正面（另開分頁）"`，或拿掉 `aria-label`，改用只給螢幕閱讀器的文字補上商品名稱。

**3. 低｜語意結構**
- `index.html:1`：相簿標題 `#merch-title` 是 `h3`，底下每張卡片也是 `h3`，兩者變成同一層。卡片標題應改為 `h4`，並同步修改 `style.css:388`、`:398`、`:404` 的 `.merch-card h3` 選擇器。
- `index.html:1`：`div.merch-album` 加了 `aria-labelledby`。一般 `div` 不支援這個屬性的命名作用，實際上不會生效。建議改成 `<section>`，或直接移除該屬性。

**4. 低（需要確認）｜色彩管理**
- 位置：`scripts/prepare-merch.py:50`，`web.save(...)` 沒有傳入 `icc_profile`。
- 風險：書籤和 NFC 的來源是手機拍的 JPG。如果它們帶有 Display P3 色彩描述檔，輸出的 WebP 會被當成 sRGB 顯示，紅色會偏淡。這次是唯讀審查，我沒有執行 Python 去確認來源是否帶描述檔。
- 建議：先確認來源。如果帶有非 sRGB 描述檔，可以加上 `icc_profile=im.info.get('icc_profile')`，或先用 `ImageCms` 轉成 sRGB。

**5. 低｜響應式：761–1100px 的平板寬度留白過大**
- 位置：`style.css:390`，`height: 310px` 在雙欄排版下沒有調整。
- 以 800px 寬估算，照片區約 244px 寬，雷射票只會顯示約 85px 高，上下各留約 110px 空白。目前的截圖沒有涵蓋這個寬度。建議把高度改成 `clamp()`，或依長寬比給不同高度。

**6. 低｜版本控制**
- 原始 zip `週邊-20261116T083208Z-1-001.zip` 放在專案根目錄，沒有被 git 追蹤，`.gitignore` 也沒有排除它，之後容易被一起 commit。建議移出專案目錄，或加進 `.gitignore`。

**7. 低｜QA 截圖不足**
- 桌面截圖的 header 顯示「動態：關閉」（`shared/motion.js:13` 的文字表示目前狀態），代表截圖不是在預設的動態開啟狀態下拍的。
- 三張截圖也都沒有拍到 Q 版流沙的待補卡、展開後的背面照片，以及平板寬度。建議在動態開啟的狀態下補拍這些畫面。

## 可選的偏好（不是缺陷）

- 第 9 張待補卡會單獨留在最後一列左欄。可以讓它 `grid-column: 1 / -1`，或維持現狀。
- 商品卡沒有用到其他拼貼元素的膠帶與些微旋轉，也沒有 `data-reveal`，看起來比較像整齊的商品格，手帖感偏弱。這屬於美術選擇。
- `.merch-enlarge` 的 12px 字偏小（`style.css:391`）。
- NFC 背面上下左右還留有約 8–12% 的灰色背景，可以再裁緊一點。
- 中文和英文之間的空格不一致：標題是「PVC 透卡」，`alt` 和 `aria-label` 裡卻是「四週年PVC」「查看NFC」。
- WebP 品質 88 可以考慮降到 80–82。目前最大的 `holder-back-1400` 約 300KB。
- 腳本可以加上裁切範圍的檢查。目前 15 組裁切座標都在原圖範圍內，所以只是預防用。

## 已確認沒有問題

- `build.mjs` 會複製整個 `assets/web`，`check.mjs` 也會檢查本機路徑。
- `versions/11-theatre-scrapbook/index.html` 只是轉址回首頁，不需要同步修改。
- 腳本處理後會去掉 EXIF（包含位置資訊），也保留了透明背景。
- 背面照片放在預設收合的 `details` 裡，並設定 `loading="lazy"`，主流瀏覽器通常要展開後才會下載。

**沒有檢查到的部分：** 我無法執行 git diff，所以沒有確認 `index.html` 除了相簿以外是否還有其他改動；另外也沒有實際在瀏覽器裡操作或量測效能。

## 審查後處理

- 依每張圖比例與手機／平板／桌面實際高度調整 sizes，避免直式縮圖不必要地選大圖。
- 連結名稱改為「查看大圖：商品正面／背面（另開分頁）」；商品標題改 h4。相簿的 role=region 已於自動可及性檢查時修正。
- 實際確認 NFC 正反面帶 Display P3，輸出 WebP 保留來源 ICC；其他照片有 sRGB 或未附 ICC，均不任意指定新的來源色域。
- 761–1100px 照片框縮至 240px 高。原始 ZIP 加入 .gitignore。
- 補拍動態開啟時的平板、缺圖卡與展開背面。
- 卡片採整齊紙框、沒有新增進場動畫，是讓商品易比較的設計選擇。
